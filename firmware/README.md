# Прошивка IP-Radio

Приёмник на **Waveshare ESP32-P4-WIFI6-Touch-LCD-5**: эфирное FM и
интернет-радио на одном экране.

Прошивка работает на плате. Интернет-радио играет со звуком, экран и
касание живые, Wi-Fi подключается, станции ищутся в каталоге и
сохраняются на карту.

> До 2026-09-15 этот файл назывался «Каркас прошивки» и утверждал, что
> логики приёмника здесь нет. Это перестало быть правдой ещё в конце
> августа, а текст остался — из-за него можно было решить, что код

## Чем собирается

| | |
|---|---|
| ESP-IDF | **5.5.3** (подмодуль внутри ESP-ADF) |
| ESP-ADF | release/v2.x |
| LVGL | 9.5 + `esp_lvgl_adapter` + BSP платы |
| Wi-Fi | через сопроцессор ESP32-C6: `esp_wifi_remote` + `esp_hosted` по SDIO |
| Язык | C, `gnu17` |

```bash
. $IDF_PATH/export.sh          # ADF_PATH должен быть выставлен
idf.py build
idf.py -p <порт> flash monitor
```

**ADF подключается локально, а не из реестра.** В `CMakeLists.txt`
верхнего уровня стоит:

```cmake
if(DEFINED ENV{ADF_PATH})
    set(EXTRA_COMPONENT_DIRS $ENV{ADF_PATH}/components)
```

Поэтому в `main/idf_component.yml` его нет и быть не должно: тот файл
перечисляет зависимости **из реестра компонентов**, а ADF туда не
входит. Без `ADF_PATH` в окружении сборка не пройдёт — интернет-радио
на ADF и держится.

### Правка ESP-IDF, без которой экран зависает

В дереве ESP-IDF внесена одна правка, вне этого репозитория:
`components/esp_driver_ppa/src/ppa_srm.c` — обход аппаратной ошибки
ESP32-P4 **DIG-734**. Без неё ускоритель поворота встаёт, и экран
замирает через секунды после начала воспроизведения.

При обновлении или переустановке ESP-IDF правка пропадёт, а зависание
вернётся. Что и зачем — [../docs/31-idf-patch-ppa.md](../docs/31-idf-patch-ppa.md).

### Своя копия esp_hosted

Драйвер связи с сопроцессором Wi-Fi лежит в `components/esp_hosted`, а не
скачивается из реестра: это версия 1.4.7 с одной правкой. Буфер приёма
SDIO перенесён из внутренней памяти в PSRAM; без этого прибор
перезагружался после нескольких переключений станций. Подключение —
`override_path` в `main/idf_component.yml`, правка и как её переносить
на новую версию — [components/esp_hosted/PATCHES.md](components/esp_hosted/PATCHES.md).

## Из чего состоит

Тридцать три модуля в `main/` и одна своя копия чужого компонента
в `components/` (см. ниже). Устройство слоями:

```
   ввод                     состояние                 железо
   ────                     ─────────                 ──────
ipradio_input   ──событие──▶ ipradio_state ──снимок──▶ ipradio_bridge
касание экрана  ──событие──▶      │                        │
                                  │                        ├─▶ ipradio_tuner    (RDA5807M)
                            ipradio_ui ◀──снимок───────────┤
                                  │                        ├─▶ ipradio_netradio (ADF)
                            экраны ui_*                    └─▶ ipradio_audio    (I²S, усилитель)
```

**Правило одного владельца.** Состояние живёт только в
`ipradio_state.c`. Никто не меняет его напрямую: модули шлют события,
автомат их разбирает и отдаёт наружу снимок. Поэтому на экране не
бывает того, чего нет в приборе.

| Модуль | Отвечает за |
|---|---|
| `ipradio_state` | конечный автомат, единственный владелец состояния |
| `ipradio_bridge` | перенос состояния на железо, по разнице |
| `ipradio_input` | кнопки и энкодеры, антидребезг, долгие нажатия |
| `ipradio_tuner` | RDA5807M: настройка, автопоиск, RDS |
| `ipradio_netradio` | конвейер ADF: `http → декодер → громкость → I²S` |
| `ipradio_net` | Wi-Fi, SNTP, каталог radio-browser |
| `ipradio_storage` | карта памяти, две копии JSON с контрольной суммой |
| `ipradio_store_format` | печать и разбор файла хранилища, перенос старого образца |
| `ipradio_selftest` | самопроверка формата хранилища при запуске |
| `ipradio_mem` | политика памяти: узлы JSON в PSRAM, учёт неудачных выделений |
| `ipradio_soak` | отладочный прогон: прибор сам листает станции, ключ `IPRADIO_DEBUG_SOAK` |
| `ipradio_preset_edit` | правка ячеек банка: имя, очистка, запись станции; без LVGL, проверяется на машине |
| `ipradio_audio` | I²S, линия приглушения усилителя |
| `ipradio_board_codec` | **временно**: штатный кодек платы ES8311 |
| `ipradio_adf_stack` | стеки задач ADF в PSRAM без патчей к ESP-IDF |
| `ipradio_watchdog` | надзор за задачами |
| `ipradio_fonts` | кириллица, кегли рисуются из TTF во время работы |
| `ipradio_ui` | главный экран, навигация между экранами |
| `ipradio_ui_*` | тринадцать экранов: меню, станции, поиск, Wi-Fi, часы, яркость, клавиатура, диагностика, ждущий, меню ячейки |

## Режимы сборки

Все ключи — в `main/board_pins.h`.

### Звуковой тракт

```c
#define IPRADIO_USE_BOARD_CODEC   1
```

**1 — временный тракт платы**, как сейчас: I²S на выводы 12/10/9 плюс
MCLK на 13, кодек ES8311 по I²C, усилитель платы NS4150B, разъём
динамика GH1.25. Так можно слушать, пока своя обвязка не подключена.

**0 — целевой тракт**: I²S на выводы 46/47/48, свой ЦАП PCM5102A,
усилитель TPA3118, штатный усилитель платы удерживается выключенным.

Переключать после того, как своя обвязка появится физически.

### Органы управления

```c
#define IPRADIO_USE_IO_EXPANDER   0
```

**0** — пять кнопок пресетов прямо на выводах процессора.
**1** — восемь через MCP23017. Драйвера расширителя пока нет.

Кнопок на приборе **сейчас нет вовсе**, поэтому всё управление
продублировано касанием. Кнопки, когда появятся, будут адресовать
первые `IPRADIO_PRESET_BUTTONS` ячеек; в банке их
`IPRADIO_PRESET_MAX`, и это разные числа намеренно.

### Отладочные выводы в журнал

```c
#define IPRADIO_DEBUG_MAIN_PULSE    1   /* память раз в три секунды      */
#define IPRADIO_DEBUG_AUDIO_FLOW    1   /* байты в I²S раз в пять секунд */
#define IPRADIO_DEBUG_CODEC_REGS    1   /* дамп регистров ES8311         */
#define IPRADIO_DEBUG_SOAK          0   /* прибор сам листает станции    */
```

Во время отладки полезны, перед отдачей прибора ставятся в 0.
`IPRADIO_DEBUG_SOAK` в работе держится в 0 **всегда**: с ним прибор
через минуту после включения начинает сам переключать станции.

### Эфирный диапазон

```c
#define IPRADIO_ENABLE_OIRT   0
```

УКВ OIRT отключён решением заказчика. Код диапазона сохранён, но
в интерфейс не выходит.

## Что работает, а что нет

**Проверено на плате:**

* панель, поворот на 90°, кириллица, касание;
* карта памяти, сохранение и чтение станций;
* Wi-Fi, получение адреса, поиск станций в каталоге;
* интернет-радио **со звуком** через кодек платы;
* все двенадцать экранов, управление касанием.

**Написано, но проверить нечем** — нет обвязки:

* эфирный приём: тюнер RDA5807M не подключён;
* кнопки, энкодеры, кнопка питания;
* целевой звуковой тракт PCM5102A + TPA3118.

**Не сделано:**

* метаданные ICY: в ADF их поддержки нет;
* строка «последняя ошибка» на экране диагностики — нужен журнал,
  переживающий перезагрузку;
* определение внешнего питания.

## Что обязательно проверять на железе

Каждая из бед в этой таблице компилировалась без единого
предупреждения. Успешная сборка о них не говорит ничего.

| Что проверить | Как выглядит отказ |
|---|---|
| Свободная внутренняя память **во время воспроизведения** | должно оставаться не меньше 30 КБ; при 2 КБ падает рукопожатие TLS и драйвер SDIO |
| Строки `adf.stack: … в PSRAM` в журнале | если их нет, стеки элементов ADF съели внутреннюю память |
| Экран **во время** проигрывания | `Failed to acquire LVGL lock` раз в полсекунды означает потерянную правку PPA |
| Отклик касания после десятка переключений станций | задержки означают, что медленное вернулось в задачу автомата |
| Запись станции и её удаление | обе операции идут под одним замком, `ipradio_storage_edit_begin` |

**Грабли, на которые уже наступали четырежды.** `ipradio_store_t` — это
около 5 КБ (после разделения банков), и на стек его класть нельзя. Обработчики касания
исполняются в задаче `lvgl`, её стека на такую копию не хватает, и
прибор уходит в перезагрузку. Для правки банка есть
`ipradio_storage_edit_begin()` / `ipradio_storage_edit_end()`.
