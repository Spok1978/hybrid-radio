# 01. Откуда берётся список интернет-радиостанций

Это ответ на вопрос «как вообще происходит поиск станций в интернете».
Ниже: как устроено интернет-радио технически, какие существуют каталоги,
что из них реально доступно DIY-устройству, и сравнение вариантов.

Все проверки помечены датой. Что не проверял — помечено явно.

## 1. Как устроено интернет-радио (техническая база)

Интернет-радиостанция — это **не файл и не «канал»**, а постоянный HTTP-поток:

```
GET /stream HTTP/1.1
Icy-MetaData: 1
        ↓
HTTP/1.0 200 OK
icy-name: Radio Record
icy-br: 128
Content-Type: audio/mpeg
        ↓ дальше бесконечно идут кадры MP3/AAC,
          а каждые icy-metaint байт вставляется врезка
          StreamTitle='Исполнитель - Трек';
```

Из этого следуют три факта, важных для конструкции:

1. **Станция = один URL.** Чтобы играть станцию, устройству нужна ровно одна
   строка вида `http://server:8000/stream`. Всё остальное — сервис.
2. **Название станции и название трека приходят внутри потока** (заголовок
   `icy-name` при подключении и врезки `StreamTitle` в процессе). То есть в
   режиме 2 «название станции» на экране можно брать прямо из потока, каталог
   для этого не нужен.
3. **Ссылка часто спрятана в плейлист-обёртку** `.pls`, `.m3u`, `.m3u8`.
   Плеер сначала скачивает маленький текстовый файл, берёт оттуда `File1=…`
   и уже тогда открывает поток. Приёмник должен уметь разворачивать обёртки.

Форматы потоков: MP3 и AAC/AAC+ — абсолютное большинство; Ogg/Opus — меньше;
HLS (`.m3u8`, нарезка на сегменты) — набирает долю у крупных вещателей.
Это влияет на выбор платформы: HLS и AAC+ тянет не всякий встраиваемый декодер.

**Вывод:** «поиск станций в интернете» = получить из какого-то каталога
пары «название → URL потока». Каталог — единственное, что нужно выбрать.

## 2. Какие каталоги существуют

### A. Radio Browser — `radio-browser.info`

Открытый общественный каталог, REST API, **без ключа и без регистрации**.

Проверено 2026-08-17 запросом `GET https://de1.api.radio-browser.info/json/stats`
(User-Agent: `ip-radio-research/0.1`):

```
software_version : 0.7.44
stations         : 62486
stations_broken  : 18
tags             : 11932
languages        : 648
countries        : 241
clicks_last_day  : 166682
```

Станций по странам (`/json/countrycodes`, тот же запрос, 2026-08-17):

| Код | Станций |
|-----|---------|
| RU  | 3186 |
| UA  | 354  |
| BY  | 106  |
| KZ  | 46   |
| DE  | 6158 |
| GB  | 2366 |
| US  | 7752 |

Как устроено обращение:

- Список серверов-зеркал берётся через DNS: A-записи `all.api.radio-browser.info`
  либо SRV-запись `_api._tcp.radio-browser.info`; документация просит выбирать
  сервер случайно и уметь переключаться на другой при отказе
  (проверено 2026-08-17: `all.api.radio-browser.info` резолвится, отдал `91.98.4.78`).
- Обязателен внятный `User-Agent` вида `ipradio/0.1` — это требование документации.
- Ключа нет, лимитов в документации не указано.
- Просят при запуске станции дёргать `/json/url/{stationuuid}` — это счётчик
  кликов, по нему строится рейтинг. Вежливость, не обязанность.

Что можно спросить (пути от корня сервера):

| Задача | Запрос |
|--------|--------|
| Станции страны | `/json/stations/bycountrycodeexact/RU?hidebroken=true` |
| По жанру/тегу | `/json/stations/bytag/jazz` |
| По названию | `/json/stations/byname/эхо` |
| По языку | `/json/stations/bylanguage/russian` |
| Гибкий поиск | `/json/stations/search?tag=rock&countrycode=RU&limit=50&order=clickcount&reverse=true` |
| Топ по кликам | `/json/stations/topclick/100` |
| Справочники | `/json/countries`, `/json/tags`, `/json/languages`, `/json/codecs` |

Ответ можно получить не только JSON — есть `/m3u/…` и `/pls/…`, то есть
API умеет сразу отдать готовый плейлист.

Серверная часть (`radiobrowser-api-rust`) открыта под AGPL-3.0 — при желании
поднимается собственное зеркало, и тогда устройство вообще ни от кого не зависит.
Оператор пишет, что держит сервис с декабря 2015 года, но гарантий не даёт.

### B. Свой файл-список (M3U/PLS/CSV)

Никакого каталога: в устройстве лежит текстовый файл со станциями, которые
ты сам выбрал. Именно так сделано в большинстве прошивок ESP32-радио
(например, `/stations.json` в ESP32-MiniWebRadio; в README того же проекта
всё ещё написано `stations.csv` — README отстал от кода, см.
[24](24-main-build-p4.md), §2).

Плюсы: ноль внешних зависимостей, работает вечно, полностью под контролем.
Минусы: нет обнаружения новых станций; когда вещатель меняет URL — чинишь руками.

### C. SHOUTcast Radio Directory API

Исторический каталог Winamp/SHOUTcast.

Проверено 2026-08-17: `GET https://api.shoutcast.com/legacy/Top500?limit=1` →
HTTP 200 с телом

```xml
<response><statusCode>460</statusCode><statusText>Missing required parameter</statusText>
<statusDetailText>Missing k</statusDetailText></response>
```

То есть **нужен ключ разработчика** (`k=`). Ключ выдаётся по заявке на портале
SHOUTcast — процедуру я не проверял. Для устройства это означает зависимость от
чужой учётки и риск отзыва ключа. Сайт каталога жив: `https://directory.shoutcast.com/`
отдал HTTP 200 (проверено 2026-08-17).

### D. Xiph / Icecast YP — `dir.xiph.org`

Каталог станций, вещающих через Icecast. Отдаёт единым дампом `yp.xml`.

Проверено 2026-08-17: `https://dir.xiph.org/yp.xml` → HTTP 200, 9 451 490 байт.
Ключ не нужен, но: сам сайт помечен как BETA, репозиторий предыдущей версии
на GitLab отмечен как obsolete, а документация Icecast просит не дёргать
`yp.xml` часто — файл тяжёлый. Охват заметно уже, чем у Radio Browser:
только Icecast-вещатели.

Годится как **резервный** источник или как оффлайн-снапшот, не как основной
поисковый интерфейс: там нет нормального поиска, есть только «скачай всё».

### E. TuneIn — `opml.radiotime.com`

Тот самый каталог, что стоит в куче бытовых интернет-радиоприёмников и
AV-ресиверов. Публичного документированного API для сторонних устройств нет;
адреса вида `opml.radiotime.com/Browse.ashx?…` известны по реверс-инжинирингу.
Хост живёт (проверено 2026-08-17, резолвится в 104.17.106.184/104.17.107.184),
но это **недокументированный интерфейс**: может закрыться в любой момент и
формально это использование чужого сервиса вне условий. Для домашней поделки
физически работает, для «сделать нормально» — плохой фундамент.

### F. vTuner / Airable

Коммерческие каталоги, которые лицензируют производители (Denon, Yamaha,
Marantz, Sonos, Bluesound, NAD, Technics — по данным обзоров рынка).
Доступ по договору с производителем устройства. Нам недоступны. Упоминаю,
чтобы было понятно, чем пользуются заводские приёмники: как правило это
vTuner (старые модели) или Airable (новые).

### G. Собственное зеркало Radio Browser

Разворачивается `radiobrowser-api-rust` на любом VPS или даже на самом Pi,
данные импортируются из общего дампа. Полная независимость, но появляется
сервер, который надо содержать. Как запасной путь — держим в уме.

## 3. Сравнение

| Критерий | A. Radio Browser | B. Свой файл | C. SHOUTcast | D. Xiph yp.xml | E. TuneIn |
|---|---|---|---|---|---|
| Ключ/регистрация | не нужен | — | **нужен** | не нужен | нет (недокум.) |
| Охват | ~62,5 тыс. станций | сколько внесёшь | большой | только Icecast | очень большой |
| Поиск по стране/жанру | да, штатно | нет | да | нет | да |
| Работа без интернета | из кеша | да | нет | из дампа | нет |
| Риск «однажды отключат» | средний (общественный проект) | нулевой | средний (ключ) | средний (BETA/obsolete) | **высокий** |
| Юридическая чистота | открытый проект | твой файл | по условиям API | открытый | сомнительно |
| Сложность в коде | низкая (REST+JSON) | нулевая | низкая | разбор 9 МБ XML | средняя |

## 4. Что предлагаю (на обсуждение)

**Гибрид A + B**, с приоритетом на локальное хранение:

1. **Radio Browser — только как «поисковик»**. Пользователь в меню выбирает
   страну/жанр/вводит название → устройство делает один REST-запрос →
   показывает найденное списком.
2. **Найденную станцию кладём в свою локальную базу** (решено 2026-08-21:
   **JSON с атомарной заменой**, см. [14](14-software-stack.md), §3 — на
   диске приёмника): название, URL потока, кодек, битрейт, страна, UUID.
   Дальше приёмник играет **из своей базы** — интернет нужен только для
   самого потока, не для каталога.
3. **Ручное добавление URL** — обязательно оставить. Это спасательный люк:
   любую станцию, которой нет в каталоге, можно вбить руками.
4. **Резерв — снапшот.** Раз в N недель можно тянуть дамп каталога и хранить
   локально, чтобы поиск работал даже при недоступности API.

Почему так: список станций — это личная настройка прибора, она не должна
зависеть от живости чужого сервиса. Каталог нужен один раз при поиске,
а не при каждом включении.

**Что решаем вместе** — см. [06-open-questions.md](06-open-questions.md), вопрос Q1.
