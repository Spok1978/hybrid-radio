> сборки без пересмотра не применяется.

Составлено 2026-08-21 по рекомендации внешнего аудита ([12](12-audit-response.md)):
конфликты выводов дешевле поймать на бумаге, чем на собранном приборе.

он не понадобится.

## 2. Что нельзя занимать и почему

- **GPIO0 / GPIO1** (конт. 27, 28) — линии опознания HAT.
- **GPIO3** — помимо I²C это единственный вывод, которым плата будится из
  halt. Пробуждением мы не пользуемся ([10](10-shutdown-and-data-safety.md)),
  но кнопку туда вешать нельзя: разорвёт обмен с тюнером.
- **Тачскрин экрана** сидит на отдельной шине i2c_csi_dsi, идущей по шлейфу
  DSI, и GPIO2/3 не занимает. **Ключ `i2c1` у оверлея панели включать нельзя** —
  он посадит тач ровно на выводы тюнера.
- **GPIO14 / GPIO15** — последовательная консоль. При отладке без монитора
  это единственный способ увидеть, что происходит на старте.

## 3. Строки для `config.txt`

Черновик, номера выводов — из таблицы выше:

```ini
# экран
dtoverlay=vc4-kms-dsi-waveshare-panel,7_0_inchC

# звук: I²S-ЦАП PCM5102A
dtoverlay=hifiberry-dac

# тюнер
dtparam=i2c_arm=on

# энкодеры: события ядра вместо опроса из Python
dtoverlay=rotary-encoder,pin_a=5,pin_b=6,relative_axis=1,steps-per-period=4
dtoverlay=rotary-encoder,pin_a=7,pin_b=8,relative_axis=1,steps-per-period=4,linux_axis=1

# кнопки: каждая — отдельный вызов оверлея, keycode обязателен и уникален
dtoverlay=gpio-key,gpio=4,label=MENU,keycode=139
dtoverlay=gpio-key,gpio=27,label=MEM,keycode=165
dtoverlay=gpio-key,gpio=22,label=PREV,keycode=105
dtoverlay=gpio-key,gpio=23,label=NEXT,keycode=106
dtoverlay=gpio-key,gpio=24,label=SEEK,keycode=217
dtoverlay=gpio-key,gpio=25,label=OK,keycode=28

# кнопка второго энкодера и кнопка MODE — тоже входы, без них софт их не увидит
dtoverlay=gpio-key,gpio=12,label=MUTE,keycode=96
dtoverlay=gpio-key,gpio=9,label=MODE,keycode=161

# питание
dtoverlay=gpio-shutdown,gpio_pin=17,debounce=3000
dtoverlay=gpio-poweroff,gpiopin=26
```

Что проверить на макете:

1. **`steps-per-period` для EC11** подбирается опытом: 1, 2 или 4, в
   зависимости от того, сколько импульсов энкодер даёт на щелчок. Правильное
   значение — когда один щелчок даёт ровно одно событие.
2. **`debounce=3000` как «удерживай 3 секунды»** — приём из практики
   сообщества, а не документированная функция. Смысл: событие возникает
   только если уровень продержался всё это время, то есть случайное касание
   прибор не гасит. Проверить, работает ли ожидаемо.
3. У `gpio-key` и `gpio-shutdown` **вывод по умолчанию — GPIO3**. Обязательно
   задавать свой явно, иначе оверлей займёт шину тюнера.
4. **`keycode` задавать обязательно и уникально для каждой кнопки.**
   В описании оверлея значение по умолчанию не документировано, а без явного
   кода кнопки в лучшем случае неразличимы для программы. Коды в блоке выше —
   рабочие значения из `linux/input-event-codes.h`, поменять можно любые,
   лишь бы не повторялись. Добавлено 2026-08-21 по итогам внешнего разбора:
   раньше `keycode` не был задан ни у одной кнопки, а для MODE и кнопки
   второго энкодера строк не было вовсе.
5. **Пункт снят 2026-08-25.** Здесь стояла оговорка: тумблер режима даёт
   уровень, а не нажатие, поэтому при старте его положение пришлось бы читать
   отдельно. Тумблер заменён кнопкой MODE без фиксации
   ([22](22-mode-switching.md)); оверлей `gpio-key` рассчитан именно на кнопку,
   читать уровень при старте больше не нужно. Режим при включении берётся
   из сохранённого состояния прибора.

## 4. Почему оверлеи ввода, а не опрос GPIO из Python

Рекомендация аудита, с которой согласен:

- антидребезг и разбор фаз энкодера делает ядро, а не наш цикл;
- события приходят через `/dev/input` (читаются, например, через `python-evdev`),
  и **не теряются**, когда процессор занят декодированием потока;
- «короткое и длинное нажатие» получается надёжнее, чем в опросе;
- меньше кода в интерфейсе и меньше поводов для гонок.

## 5. Прочие решения по софту

| Тема | Решение |
|---|---|
| ОС | **Raspberry Pi OS Lite, 64-битная, минимум Bookworm.** Bookworm — потому что там мейнлайн-оверлей панели; Lite — потому что интерфейс свой и рабочий стол не нужен |
| Интерфейс | PyQt5 или pygame поверх KMS, без браузера — как решено в [03](03-controller-platform.md) |
| Воспроизведение | MPD или mpv в фоне. **Проверить `mpd --version` на наличие `hls+https`**: HLS в MPD работает только через плагин ffmpeg. У mpv HLS родной — если с MPD будут сложности, берём mpv |
| Плейлисты | Разворачивание `.pls` / `.m3u` / `.m3u8` делать своим кодом **до** передачи URL плееру, а не полагаться на плеер |
| Надёжность | Включить аппаратный watchdog (`bcm2835_wdt`) и надзор systemd за службой воспроизведения: у прибора нет клавиатуры, он должен сам выходить из зависания |
| Время загрузки | Цель — **играет менее чем через 20 с** после подачи питания: Lite-образ, отключение лишних служб, автостарт последней станции до отрисовки меню |
| Структура кода | Ядро (база станций, тюнер, воспроизведение) — отдельный модуль с API поверх unix-сокета или localhost. Тогда веб-слой, если когда-нибудь понадобится, надстраивается без правки ядра ([06](06-open-questions.md), Q9) |
