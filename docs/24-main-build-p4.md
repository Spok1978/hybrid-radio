# 24. Основная сборка переносится на ESP32-P4

Решение заказчика от 2026-08-26. Отменяет решение от 2026-08-17 «Собираем
на Pi, как заказано» ([08](08-cost-and-board-choice.md), §10) и меняет ответ
на вопрос Q3.

Вместе с ним принято: **формат списка станций берём тот, что у сборки на
ESP32-P4** — штатный формат прошивки-основы, а не наш собственный.

## 1. Что стало основным

| Что | Было (2026-08-17) | Стало (2026-08-26) |
|---|---|---|
| Плата | Raspberry Pi 3 Model B+ | Waveshare ESP32-P4-WIFI6-Touch-LCD-5 |
| Экран | 7″ DSI 1024×600, альбомный | 5″ DSI 720×1280, **книжный** |
| Софт | своё приложение на Python, MPD/mpv, systemd | ESP-IDF, база `schreibfaul1/ESP32-MiniWebRadio` |
| ЦАП | PCM5102A отдельной платой | ES8311 на плате |
| Список станций | свой файл с атомарной заменой | штатный `/stations.json` прошивки на карте |
| Часы | DS3231 отдельным модулем | свои у P4, на плате разъём батарейки |

Ревизия на Pi не выбрасывается. Документы [13](13-gpio-map.md),
[15](15-wiring-breadboard.md), [16](16-connection-list.md) остаются
проработанной альтернативой и получают пометку в шапке; [10](10-shutdown-and-data-safety.md)
и [14](14-software-stack.md) применимы частично — там, где речь про Linux,
не применимы вовсе.

## 2. Формат списка станций: в проекте он записан неверно

В документах проекта сказано, что MiniWebRadio держит станции в
`stations.csv`, до 999 записей ([03](03-controller-platform.md), §3;
[08](08-cost-and-board-choice.md), §9). **Это устарело.**

Проверено 2026-08-26 по исходникам ветки master репозитория
`schreibfaul1/ESP32-MiniWebRadio`, файл `src/mwr_src/function.hpp`, метод
`stationManagement::updateStationsList()`:

- файл открывается как **`/stations.json`** в корне карты —
  `if (!SD_MMC.exists("/stations.json")) { return; }`, далее
  `File file = SD_MMC.open("/stations.json");`
- разбор идёт по четырём полям в записи:

```c++
if (item == 0) { m_stations.fav.push_back(buff[0]); }
if (item == 1) { m_stations.country.push_back(x_ps_strdup(buff)); }
if (item == 2) { m_stations.name.push_back(x_ps_strdup(buff)); }
if (item == 3) { m_stations.url.push_back(x_ps_strdup(buff)); }
```

Одна станция — массив из четырёх строк, порядок: признак избранного,
код страны, название, URL потока:

```json
["*", "DE", "0N 70s", "http://0n-70s.radionetz.de:8000/0n-70s.mp3"]
```

`README.md` того же репозитория всё ещё пишет про `stations.csv` и 999
станций — README отстал от кода. **Предел в 999 записей по исходнику не
проверялся**, брать его как факт нельзя.

## 3. Что из этого следует

**В плюс:** формат и так JSON, поэтому решение «JSON, а не SQLite»
([14](14-software-stack.md), §3) не отменяется, а подтверждается чужой
реализацией. Файл читается глазами и правится руками — как и хотели.

**В минус:** в записи всего четыре поля. Из того, что мы собирались хранить
про станцию ([14](14-software-stack.md), §3) — `name`, `url`, `codec`,
`bitrate`, `country`, `stationuuid`, `last_verified`, `source` — влезают три:
`country`, `name`, `url`. Не влезают:

| Поле | Зачем было нужно |
|---|---|
| `stationuuid` | отметить клик в Radio Browser и подтянуть новый URL, если вещатель его сменил |
| `codec`, `bitrate` | показать на экране, отсеять неиграбельное |
| `last_verified` | понимать, когда станцию последний раз проверяли |
| `source` | отличать найденное в каталоге от вбитого руками и импортированного |

**И главное: места для эфирных пресетов в этом формате нет вообще.**
MiniWebRadio про УКВ/FM ничего не знает, а в [22](22-mode-switching.md) принят
единый банк из 8 ячеек, где запись несёт тип `fm` или `net`. Либо эфирные
пресеты живут отдельным файлом, либо формат станций расширяется — и тогда это
уже не «штатный формат прошивки», а её форк.

Решено 2026-08-26: мастером становится наш файл, `/stations.json` —
производная проекция. Разбор и обоснование — [25](25-station-storage.md), §9.

## 4. Что этот перенос открывает заново

| Вопрос | Почему открылся |
|---|---|
| **Q12** — раскладка интерфейса | [05](05-display-and-ui.md) весь построен на 1024×600 альбомной ориентации, а панель 720×1280 **книжная**. **Решено 2026-08-26:** раскладка альбомная, кадр поворачивается на 90° средствами PPA, дисплейный порт пишем сами |
| ~~**Q13**~~ — пресеты и поля станции | **закрыт 2026-08-26**: наш файл — мастер, `/stations.json` — проекция. [25](25-station-storage.md), §9 |
| **Q14** — сохранность данных | [10](10-shutdown-and-data-safety.md) построен на overlayfs, `remount ro/rw` и атомарном `rename()` в Linux. На ESP32 с картой FAT ничего из этого нет. **Решено 2026-08-26:** ставим батарею в штатный разъём платы; остаётся признак пропадания внешнего питания и проверка гарантий FATFS/NVS |
| **Q11** — кнопки пресетов | остаётся открытым, но теперь это вопрос основной сборки, а не запасной |

Кроме того, у платы **дисплей 720×1280 не из списка, поддерживаемого
MiniWebRadio** ([08](08-cost-and-board-choice.md), §9) — дисплейный порт под
HX8394 пишется нами. Это было известно при заказе и учтено в оценке 74 балла
([21](21-board-search-criteria.md)), но теперь это работа по основной сборке,
а не по запасной.

## 5. Что переносится без изменений

- эфирный тракт: тюнер RDA5807M, антенна, коаксиал — I²C на гребёнке;
- органы управления: два энкодера, кнопки, кнопка MODE ([22](22-mode-switching.md)),
  громкость и mute на энкодере 2 ([23](23-volume-control.md)) — меняются только
  номера выводов;
- усилитель TPA3118D2 и динамик 4 Ω, если 2 Вт комплектного мало;
- силовой узел 12 В — только вместе с TPA3118, сама плата питается от USB-C;
- требования [00](00-requirements.md) целиком, включая R4.1.
